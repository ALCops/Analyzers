# Review instructions for ALCops

Two parts. The first is specific to this repository and names the `.claude/rules/*.md` file that holds the reasoning behind each check; open that file before confirming a finding of that kind and cite it. The second is the NAV SDK checklist maintained in the nav-sdk-docs repository (`templates/REVIEW.md` in https://github.com/ALCops/nav-sdk-docs); it is pasted here because review instructions are not expanded. When it changes there, update this copy.

## ALCops house rules

Severity: a finding is a **correctness** finding when it changes what a rule reports, whether the analyzer loads in `alc` or the editor, or whether the netstandard2.1 build compiles. Findings about the `.claude/` documentation contract are nits unless the change adds a rule without its rule doc.

| Check | Why | Reasoning lives in |
|---|---|---|
| An analyzer that is not `[DiagnosticAnalyzer] public sealed class X : DiagnosticAnalyzer`, or that derives from `ALCopsDiagnosticAnalyzer` / `{Cop}Analyzer` | Deriving from a Common-based type makes `alc` fail with `AL1003`; the harness is test-only. | `.claude/rules/analyzer-exception-harness.md`, `.claude/rules/analyzer-development.md` |
| A callback that does not start with the `IsObsolete()` check | Reporting on obsolete code is noise the project has decided against. | `.claude/rules/analyzer-development.md` |
| A direct `SymbolKind.X`, `PropertyKind.X`, `OperationKind.X`, `SyntaxKind.X` or `NavTypeKind.X` reference instead of `EnumProvider` | Enum ordinals differ between the SDK versions the same binary runs against; `EnumProvider` resolves by name with an inert fallback. Also check `!= default` guards on `SymbolKind` (its default is `Module`). | `.claude/rules/analyzer-development.md`, `.claude/rules/netstandard21-compatibility.md` |
| `GetSymbol()` on an operation instead of `GetSymbolSafe()`; `ValueText` or `ToString()` comparisons to identify symbols or property values; raw `StringComparison.OrdinalIgnoreCase` on AL identifiers instead of `SemanticFacts` | `GetSymbol()` throws on some operation shapes; text comparison misses quoted, qualified and namespaced identifiers; AL name equality has its own rules. | `.claude/rules/symbol-resolution.md` |
| A rule that touches record receivers but handles only the named-variable form, or fixtures that lack the `NamedVariable` / `RecSelf` / `BareSelf` / `ThisSelf` set plus the tableextension variant | The four receiver forms bind differently; missing one is the most common false-negative report. | `.claude/rules/record-receiver-forms.md` |
| Mutable instance fields; accumulate-here report-there patterns; per-invocation registrations where a per-body registration would do | Instances are shared across passes and projects; per-file passes see one file; cost is paid per callback. | `.claude/rules/sdk-analysis-scope.md`, `.claude/rules/analyzer-performance.md` |
| A C# feature or SDK member that does not exist on `netstandard2.1` used without `#if NETSTANDARD2_1` or a version gate; a change that was not built for all three target frameworks | Local builds target `net10.0` only; the CI matrix builds `netstandard2.1;net8.0;net10.0` and analyzers evaluate one compilation at a time. | `.claude/rules/netstandard21-compatibility.md` |
| Tests: `[TestCase("X")]` without `X.al`; `NoDiagnostic` fixtures without `[|...|]` markers; `expected.al` that still contains markers; `TestCodeFix` given an id string or `TestFixAll` given a descriptor; a `this` fixture without `SkipTestIfVersionIsTooLow`; a fixture that does not compile without the `InDocumentWithErrors` arrangement | Each of these passes for the wrong reason or fails with an unrelated message. | `.claude/rules/testing.md` |
| A new rule without `DiagnosticIds`, the three resx entries, a `DiagnosticDescriptors` entry with the `alcops.dev` help URI, and `.claude/rules/diagnostics/{id}-{slug}.md`; a new CodeFix without the rule doc's `## CodeFix` section; a changed design decision without its rule-doc row | The rule doc is the contract false-positive triage reads first; the help URI is what users click. | `CLAUDE.md` (Keeping `.claude/` in sync), `.claude/skills/new-analyzer/references/rule-doc.md` |
| `ALCopsSettings.cs` changed without `alcops.schema.json` (or the reverse) | A parity test enforces it; the finding saves a CI round-trip. | `.claude/rules/settings-schema.md` |
| Issue or PR numbers in code comments, XML docs or `.claude/` general guides; measurements or "not yet implemented" phrasing in general guides | The repository keeps deep context in rule docs and GitHub, not in code; `Validate-Rules.ps1` rejects the stale-fact patterns. | `CLAUDE.md` (Workflow), `.claude/scripts/Validate-Rules.ps1` |

Do not report: formatting (enforced by `dotnet format` in CI), analyzer warnings the build already turns into errors, or suppressions that carry a reason in `.editorconfig`.

## NAV SDK checklist

## What you are reviewing

This repository contains `DiagnosticAnalyzer` and `CodeFixProvider` implementations for the Business Central AL compiler SDK (`Microsoft.Dynamics.Nav.CodeAnalysis` and `Microsoft.Dynamics.Nav.CodeAnalysis.Workspaces`). The SDK looks like Roslyn but is not Roslyn: it has no public documentation, several Roslyn-shaped members behave differently, and the same analyzer binary runs against three SDK generations (netstandard2.0 at the 12.0 floor, net8.0 at 16.0, net10.0 at 18.x). Findings that assume Roslyn semantics are usually wrong; findings about the SDK's real behaviour are the valuable ones.

The evidence for every check below is the nav-sdk-docs plugin: concept pages under `docs/` and per-version availability tables under `reference/`. Find that tree before confirming a finding: the sibling checkout `../nav-sdk-docs`, or the plugin cache `~/.claude/plugins/cache/nav-sdk-docs/**` (glob for the `docs/` directory). The decompiled SDK is the sibling `../nav-sdk-source`; read it at a tag with `git -C ../nav-sdk-source show <tag>:<path>`. Before you confirm a finding of one of the kinds below, open the named docs page, check that the code really does what the page says will misbehave, and cite the page (and the source path it cites) in the finding. A finding that only says "Roslyn does X" is not evidence and must be dropped.

## Severity

Treat as **correctness** findings, not nits: anything that changes what the analyzer reports in the editor host versus `alc`, makes it throw (the executor converts that to a silent `AD0001`), makes it fail to load (`AL1003`), or makes it fail to compile on one of the three target frameworks. Style, naming and formatting are out of scope for this section.

## Analyzer checks

| Check | Why it is wrong | Evidence |
|---|---|---|
| State collected in one callback and reported in another (symbol actions filling a collection that a `CompilationEnd` or later symbol action reads; static or instance fields mutated during analysis) | The editor runs per-file passes that deliver only the edited file's symbols and module-only passes that deliver none; the collection is partial or empty there and complete only under `alc`. Callback order is not a contract and callbacks run concurrently. | `docs/50-diagnostics/driver-and-scope.md` (pass matrix, pitfalls), `docs/50-diagnostics/diagnostic-analyzer.md` (concurrency) |
| Mutable instance fields on the analyzer, or expensive work in `Initialize` / `RegisterCompilationStartAction` (file I/O, reflection scans, large indexes) | One instance serves every compilation of a project and `Initialize` re-runs on every pass, including every keystroke in file scope. | `docs/50-diagnostics/diagnostic-analyzer.md` (lifetime), `docs/50-diagnostics/analysis-context-and-registrations.md` (storage) |
| Relying on `SupportedVersions` to keep start-up code from running on old runtimes | The gate is per callback; `Initialize` and `CompilationStart` callbacks always run. Node actions are also skipped entirely on trees without a runtime version while symbol actions fall back to the current release. | `docs/50-diagnostics/version-compatibility.md` |
| `RegisterSyntaxTreeAction` used for a rule that must show while typing; `RegisterSemanticModelAction`, `RegisterCodeBlockAction`, `RegisterOperationBlock*Action` used at all | Syntax-tree actions do not run in per-file passes; the others have no shipped cop usage and operation-block actions have not been observed to fire in test harnesses. | `docs/50-diagnostics/driver-and-scope.md`, `docs/50-diagnostics/analysis-context-and-registrations.md` |
| Registering an operation action from a `CompilationStartAnalysisContext` | Does not exist in this SDK (compile error); the pattern must use a `ConditionalWeakTable<Compilation, T>` from a top-level operation action, or symbol/code-block actions from the start context. | `docs/50-diagnostics/analysis-context-and-registrations.md` |
| `RegisterSymbolAction` / `RegisterSyntaxNodeAction` / `RegisterOperationAction` with an empty kinds array, or a diagnostic id reported that is not in `SupportedDiagnostics` | Throws inside the callback; the executor turns it into `AD0001` and the rule silently reports nothing. | `docs/50-diagnostics/analysis-context-and-registrations.md`, `docs/50-diagnostics/diagnostic-analyzer.md` |
| An SDK member used without a guard although the `reference/` row says `no` or `changed` at `ns2.0 12.0` (or `yes (net10.0)` only); a `SyntaxKind` / `OperationKind` / `SymbolKind` value that is `no` at a floor; a hard-coded enum ordinal | Compiles locally against the latest SDK and fails in the netstandard build or at run time on the older SDK; enum ordinals are positional and shift between versions. | `reference/README.md` (legend), the member's row, `reference/Microsoft.Dynamics.Nav.CodeAnalysis/enums/` |
| `SemanticModel.GetSymbolInfo` or re-binding syntax inside an operation callback; identifying a symbol by comparing syntax text or `ToString()`; raw `StringComparison.OrdinalIgnoreCase` on AL identifiers | The operation tree already carries the bound symbol; text comparison misses qualified, quoted and namespaced forms; AL name equality has its own rules. | `docs/30-semantic-model/symbol-info-and-binding.md`, `docs/30-semantic-model/semantic-facts.md`, `docs/40-operations/operation-model.md` |
| Receiver handling that assumes `Instance` is a variable reference (misses `Rec.`, bare self-calls, `this`) or ignores `IConversionExpression` wrappers around arguments | The four receiver forms bind to different operation shapes; conversions wrap arguments implicitly. | `docs/40-operations/receivers-and-conversions.md`, `docs/40-operations/invocation-and-arguments.md` |
| `MessageFormat` placeholders that do not match the arguments passed to `Diagnostic.Create`; relying on `Diagnostic.Equals` to de-duplicate; using `WellKnownDiagnosticTags.Unnecessary` to fade code; positional custom tags after `helpLinkUri` | Format mismatches are swallowed at run time; equality compares arguments by reference; fading comes from the descriptor's `isUnnecessary` flag; the constructor has two boolean parameters before the tags. | `docs/50-diagnostics/descriptors-and-diagnostics.md` |
| Reporting on a node in another file than the declaration being analysed, or on `Location.None` for something that has a source position | Per-file passes are not clipped to the file; a diagnostic on another file appears there and disappears on that file's own pass. | `docs/50-diagnostics/driver-and-scope.md` |
| An analyzer whose `SupportedDiagnostics` is empty or built from code that can throw; a base class or static initializer that touches an assembly the loader cannot resolve | Empty or throwing `SupportedDiagnostics` silently drops the analyzer; construction failures surface only as `AL1003` at load time. | `docs/50-diagnostics/diagnostic-analyzer.md`, `docs/60-code-fixes/code-fix-provider.md` |

## Code-fix checks

| Check | Why it is wrong | Evidence |
|---|---|---|
| `root.FindNode(context.Span)` without `getInnermostNodeForTie: true`, or without checking the node's kind | The smallest node containing the span may be a token's parent rather than the node the analyzer reported on. | `docs/60-code-fixes/code-fix-provider.md` |
| Semantic work in `RegisterCodeFixesAsync` that the `CodeAction` callback could do lazily | The host calls it for every lightbulb request. | `docs/60-code-fixes/code-fix-provider.md`, `docs/60-code-fixes/code-actions.md` |
| No `GetFixAllProvider` override; `BatchFixer` when several fixes edit one shared ancestor node; an equivalence key that differs between the provider and its tests | Without the override there is no fix-all; the batch fixer merges text edits and conflicts on a shared node; a key mismatch makes fix-all silently short-circuit. | `docs/60-code-fixes/fix-all.md`, `docs/60-code-fixes/code-actions.md` |
| Rewrites that rebuild nodes from scratch instead of editing the existing ones; trivia dropped or fabricated (a `;` before `else`, lost comments) | `SyntaxEditor` and `WithX` keep trivia only when the original nodes are reused. | `docs/60-code-fixes/syntax-editor-and-editing.md` |
| Data passed from analyzer to fix through anything other than `Diagnostic.Properties`; a fix that needs facts the diagnostic does not carry | `Properties` is the only channel that survives filtering; `AdditionalLocations` reaches the fix too but nothing else does. | `docs/50-diagnostics/descriptors-and-diagnostics.md` |
| A fix assembly whose file name starts with `Microsoft.` or `System.`; a fix provider that is not public, abstract, or lacks a parameterless constructor; a stray dependency in the fix assembly | The host never scans such assemblies; one failing export drops every fix in the session with no diagnostic. | `docs/60-code-fixes/code-fix-provider.md` |

## What not to report from this section

Style, naming, formatting, and anything already enforced by the build's static analysis. Do not report Roslyn idioms that this SDK simply lacks unless the code tries to use them.
